# 详细使用说明

[返回首页](../README.zh-CN.md)

## 先看效果

如果习惯使用 Git，可以直接克隆。需要 Node.js 22+ 和 npm：

```sh
git clone https://github.com/msu1201/delivery-board.git
cd delivery-board
npm ci
npm run demo
```

也可以点击 **Code → Download ZIP**，解压后在工具目录运行 `npm ci` 和 `npm run demo`。两种方式得到的是同一个应用，任选一种即可。

会自动打开浏览器。终端输出实际地址和进程 PID；已有端口被占用时使用其他空闲端口，不停止其他服务。再次运行可以复用看板。

## 接到自己的项目旁边

仍然在工具目录执行，把示例路径换成自己的项目：

```sh
npm run init -- "/你的项目路径"
npm run open -- "/你的项目路径"
```

只创建项目里的 `.delivery-board` 目录，包含配置、空任务图和维护说明；不会修改业务代码，也不会覆盖已有看板。初始化不会自动分析代码并猜测任务。

你可以按[数据格式](../docs/ADAPTER-CONTRACT.md)填写，也可以把[配套 Skill](../skills/delivery-board/SKILL.md)交给编码助手，根据你确认的 roadmap 和任务文档整理。首次使用只需让 Agent 直接读取仓库里的 Skill 文件，不需要复制安装。`init` 负责创建空配置，按 Skill 工作的 Agent 才负责整理项目事实；它不能凭空生成可信的完成状态。

```sh
node src/entry.js check "/你的项目路径"
```

可选：在工具目录运行一次 `npm link`，之后在任意目录使用 `delivery-board open "/你的项目路径"`。这是本地命令链接，不需要 npm 上已经有同名发布包。

## 已经在做的项目，任务是怎样整理出来的？

| 部分 | 做什么 |
| --- | --- |
| 看板应用 | 读取配置允许的保存记录并展示；可读取本地 Git 元信息，但不主动查询远端 GitHub/CI。 |
| `init` 命令 | 建立空的 `.delivery-board` 配置，不分析项目，也不覆盖已有记录。 |
| Agent + Skill | 盘点项目、整理任务与分组、核对依赖和状态，并在后续工作中维护记录。 |

**记录完整时**，Agent 从已确认的 roadmap、需求、任务清单、交接记录和验收证据开始。Git 历史能说明什么变过、什么时候变的；相关且获授权的 Issue、PR、CI 也可以补充依据。看板可以显示这些已保存的结论，“看板不主动查询”不代表“接入 Agent 不能读取”。

**记录不完整时**，先建立“今天的项目基线”，不补写虚构的历史。Agent 查看已有能力、入口和可用测试，再针对项目目标、当前优先事项等关键缺口与你核对，提出模块／阶段和任务草稿。建议结构要标明是提案；目录结构不是阶段顺序，分组也不意味着依赖。

发现代码只能说明存在实现；测试只能说明实际覆盖的范围，不能证明人已验收。缺少依据时状态为 `unknown`，依赖需要证据或明确的规划决定。可以先展示一张有用但不完整的图，并记录待确认项，再逐步补齐；不能宣称已经还原了所有历史任务。详见[首次盘点流程](../skills/delivery-board/references/bootstrap.md)。

## 为什么有 Skill？为什么还要下载代码？

**应用是运行看板的程序，Skill 是给 Agent 的工作说明。** Skill 教 Agent 怎么把项目事实整理成看板记录、如何维护依赖，以及怎样区分验证、验收和交付。只复制说明文件不会安装应用和依赖，所以仍需 clone 或下载应用。

- **第一次试用**：用[首页提示词](../README.zh-CN.md#把这段话交给你的-agent)，让 Agent 直接读仓库里的 Skill；不用安装。
- **以后经常使用**：可选地把整个 `skills/delivery-board` 目录复制到 Agent 支持的技能目录，使工作流程更容易重复使用。仍需告诉 Agent 应用位置；具体发现方式取决于该 Agent 的设置。
- **不支持 Skill 的 Agent**：每次明确让它读取这个文件即可。

安装 Skill 不会启动常驻服务，也不保证所有未来会话都会自动维护记录。后续工作仍应明确遵循记录维护流程。

## 项目变了，看板也会变

计划调整确认后，先更新项目记录。页面可见时，每次读取完成后约五秒再次读取；可暂停，随时手动刷新。切到后台后暂停轮询。内容没变时不重画图；更新时保留视野与仍然存在的选择。

打开虚构演示，再在另一终端运行：

```sh
node scripts/evolve-demo.js examples/travel-demo
```

观察新增任务、依赖变化和当前工作切换。恢复原演示：

```sh
node scripts/evolve-demo.js examples/travel-demo --reset
```

看板同步的是**最新成功读取的保存记录**。聊天中的想法不会自动成为事实；配套 Skill 负责按工作流程维护记录，不是常驻执行器。读取出错时显示过期警告并保留旧图。

## 状态含义

蓝色进行中、绿色完成、紫色部分完成、橙色待验收、红色受阻、白色待开始、灰色未知。深色双边框表示选中。分组的 4/7 是完成了七项中的四项，不是正在做第四项。产品任务仅技术验证通过仍不等于验收或交付。

闭环有独立的本地验证、验收与交付记录，不能用关联任务的数量替代。缩略地图保留整体位置；详情栏可以拖宽。

## 安全边界与退出

看板只监听本机回环地址，只读配置允许的文件，没有业务写入接口、模型调用或遥测。初始化写入三个设置文件；演示脚本只改虚构演示。项目记录是否加入 Git 由你决定，工具不会擅自修改 `.gitignore`。

启动的是独立进程。按终端给出的 PID 在系统进程工具中停止，再删除工具目录即可移除应用；`.delivery-board` 记录和复制的 Skill 可以分别保留或删除。若使用了全局链接，可执行 `npm unlink -g delivery-board`。

当前已验证 macOS 本地环境；其他系统需要独立验收。MIT 许可证；尚未声称已发布 npm 包、公开演示站点或已通过所有平台验证。完整命令与开发测试见 [English README](../README.md)。
