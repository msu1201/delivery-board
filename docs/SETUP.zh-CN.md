# 详细使用说明

[文档目录](README.md) · [English](SETUP.md)

希望 Agent 代为操作，可以直接用[首页提示词](../README.zh-CN.md#把这段话交给你的-agent)。以下是手动步骤。

## 先看效果

需要 Node.js 22+ 和 npm：

```sh
git clone https://github.com/msu1201/delivery-board.git
cd delivery-board
npm ci
npm run demo
```

也可以选择 **Code → Download ZIP**，解压后在该目录运行 `npm ci` 和 `npm run demo`。

- 浏览器会自动打开，终端显示地址和进程 PID。
- 工具会避开已占用端口；再次运行可复用看板。
- 使用 `--no-open` 可以只输出地址，不打开浏览器。
- 看板以独立进程运行，不安装系统服务。

## 接到自己的项目旁边

首次填写正式任务图前，先按[项目梳理流程](DISCOVERY.md)阅读资料、讨论缺口并确认具体路线。确认之前，草稿与正式记录分开保存。

在工具目录执行，替换项目路径：

```sh
npm run init -- "/你的项目路径"
```

这会在项目的 `.delivery-board` 目录创建三个文件：

| 文件 | 用途 |
| --- | --- |
| `config.json` | 来源与读取权限 |
| `graph.json` | 空任务图 |
| `WORKFLOW.md` | 记录维护说明 |

已有设置不会被覆盖。`init` 不扫描代码；请 Agent 按[配套 Skill](../skills/delivery-board/SKILL.md)整理记录，也可以按[数据格式](ADAPTER-CONTRACT.md)手动填写。

核对不确定的状态和依赖后，校验并打开：

```sh
node src/entry.js check "/你的项目路径"
npm run open -- "/你的项目路径"
```

可选：在工具目录运行 `npm link`，之后便可在其他目录使用 `delivery-board open "/你的项目路径"`。这是本地命令链接。

## 已有项目怎样整理任务？

| 现有资料 | Agent 如何使用 |
| --- | --- |
| 路线图、需求、任务和交接记录 | 整理任务、分组与范围 |
| 本地 Git 历史 | 确认改过什么、何时改的 |
| 相关且已授权的 Issue、PR、CI | 补充证据记录 |
| 有代码和测试，但历史不完整 | 盘点当前能力，提出当前项目的任务草稿 |

目标或优先级缺失时，再向你确认。建议的阶段划分要标为提案，缺少依据的状态保留 `unknown`。待确认问题记在设置说明和任务记录中，之后逐步补齐。

有代码只能说明存在实现，测试只能证明实际覆盖的范围，都不能证明人已验收。依赖需要证据或明确的规划决定；分组不自动代表阶段顺序。

第一张图可以不完整。不要猜完成百分比，也不要宣称找回了全部历史任务。详见[首次盘点流程](../skills/delivery-board/references/bootstrap.md)。

## 项目变了，看板也会变

确认调整后，更新项目记录和受影响的适配器映射，再校验。看板显示最近一次成功读取的结果。

| 情况 | 页面行为 |
| --- | --- |
| 页面可见且开启自动刷新 | 每次读取完成后五秒再次读取 |
| 页面在后台 | 暂停轮询 |
| 记录没变 | 保留原图 |
| 记录有变化 | 保留缩放，以及仍然存在的选中项 |
| 读取失败 | 保留旧图，并显示过期警告 |

可以暂停自动刷新，也可以随时手动刷新。聊天中的想法要先写进记录；Skill 是 Agent 的工作说明，不是常驻执行器。

### 试一次计划变更

打开虚构演示后，在另一终端运行：

```sh
node scripts/evolve-demo.js examples/travel-demo
```

你会看到新增恢复任务、依赖变化和当前工作切换。变化来自实际保存的演示记录。脚本拒绝修改非演示项目，以及自行改过的演示状态。

恢复原演示：

```sh
node scripts/evolve-demo.js examples/travel-demo --reset
```

## 怎样读进度？

🔵 进行中 · 🟢 完成 · 🟣 部分完成 · 🟠 待验收 · 🔴 受阻 · ⚪ 待开始 · ◻ 未知

- 深色双边框表示选中。**4/7 表示七项任务中完成四项**，不表示第四步，也不代表整体交付。
- 技术和文档任务可以通过验证计为完成；产品任务需要验收。
- 闭环的验证、验收、交付分别记录，不能用关联任务数量替代。未记录的范围保持未知。
- 用缩略地图、定位当前、分组展开和闭环筛选浏览；拖动详情栏分隔线可加宽，查看全图可回到整体视野。

## 怎样使用 Skill？

应用负责运行看板，Skill 告诉 Agent 如何整理和维护记录。

| 使用方式 | 设置方法 |
| --- | --- |
| 首次使用 | 让 Agent 直接读取仓库的 `skills/delivery-board/SKILL.md`，无需安装。 |
| 经常使用 | 可将整个 `skills/delivery-board` 文件夹复制到支持的技能目录，并告诉 Agent 应用位置。识别方式取决于 Agent 设置。 |
| Agent 不支持 Skill | 每次直接引用该文件。 |

复制 Skill 不会安装应用或依赖，也不会启动后台进程。后续会话仍需遵循记录维护流程。

## 本地文件与隐私

- 看板只监听本机回环地址，只读配置允许的文件和证据，没有业务写入接口、模型调用或遥测。
- Git 和 CI 记录不能证明业务完成；看板不会查询远端 CI。
- 安装需要网络，日常本地查看不需要。
- `init` 只写设置文件，演示变更脚本只写虚构记录。
- `.delivery-board` 是否加入 Git 由你决定；工具不会自动将它加入忽略列表。

## 检查安装

```sh
npm test
npm run test:browser
node tests/evolution-browser.mjs
node tests/auto-refresh-browser.mjs
```

浏览器检查需要 Chrome，必要时设置 `CHROME_PATH`。当前已验证 macOS，Windows 和 Linux 尚待验证。

## 停止或移除

1. 确认启动时的 PID 仍属于这个看板，再用系统进程工具停止。详见[启动与恢复](LAUNCHER.md)。
2. 删除工具目录即可移除应用。
3. 项目的 `.delivery-board` 记录可以单独保留或删除。
4. 移除复制的 Skill。用过 `npm link` 的话，执行 `npm unlink -g delivery-board` 撤销链接。

## 与上次已看相比有什么变化？

默认手动刷新。本地读取、比较和高亮不调用模型，不消耗模型 token；Agent 分析项目或维护记录的模型用量另计。

首次成功打开会建立比较起点。刷新不会自动标记已看。摘要分别列出任务增删、更新、依赖调整、验证、验收和交付；图中变化节点带柔和光圈和 ✦ 标记。查看变化可看到前后对比及删除项，定位变化可逐个查看仍存在的任务。

工作记录显示“未读”或“有更新”，展开本轮详情后标为已读；之后有补充又会提醒。标记全部已看会确认当前显示的快照，过期或读取失败时不能确认。

已读状态保存在这个浏览器的本地存储，按看板地址与项目来源区分，包含已查看任务数据和历史内容签名，不跨设备同步。清除浏览器数据或改变看板地址后需要重新建立起点。存储不可用或已满时，会显示无法持久保存的提示，本页仍可比较。图中高亮保持静态，不移动节点。
