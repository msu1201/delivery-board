# 80 秒演示脚本

仅录制虚构旅行规划 demo。使用独立副本演示计划变化，避免改动默认示例或真实项目。字幕里的“自动更新”指已保存记录被读取，不指 AI 自主规划。

| 时间 | 画面与操作 | 口播 / 字幕 |
| --- | --- | --- |
| 0–8 秒 | 看板全景，多个分支和状态 | “AI 写了很多代码，但我更想知道：这条用户旅程，到底能不能交付？” |
| 8–20 秒 | 选择一条旅行规划旅程，展开相关任务和前置依赖 | “这里把任务和依赖放到一起。点一条旅程，就能看它涉及哪些工作。” |
| 20–32 秒 | 点开本地验证完成、仍待验收的记录 | “验证、验收、交付是三件事。测试过了，不代表用户已经验收。” |
| 32–43 秒 | 展示阻塞项、负责方及下一步记录 | “卡住的位置也有对应记录，不用只看一个完成百分比。” |
| 43–58 秒 | 分屏显示虚构的已批准计划变更与保存记录操作；使用随包提供的 demo 演进脚本，具体命令以 README 为准 | “现在模拟一次已批准的计划调整。先把变化写入记录：任务、范围和旅程引用一起维护。” |
| 58–68 秒 | 回到开启自动刷新的看板，等待下一次读取，展示变化后的图和成功读取时间 | “保存以后，页面每 5 秒检查一次。刷新只读文件，不调用模型。” |
| 68–76 秒 | 展示 skill 文件及 `init`、`open` 命令片段 | “配套 skill 帮 AI 维护记录。初始化只建立看板文件，后续再按真实计划整理。” |
| 76–80 秒 | 结束画面 | 预发布：“正在整理公开版。” 已正式发布才使用：“先下载，试试虚构 demo。” |

录制前确认演进脚本的实际变化，并让镜头、口播和保存后的记录一致。不要通过剪辑暗示尚未保存的聊天已被看板读取。

## 四张配图文案

1. **封面｜AI 写了很多，项目到底到哪了？** 虚构旅行项目全景，展示真实分支，不用虚构增长数据。
2. **任务有依赖，旅程有范围。** 选中旅程展示覆盖任务和前置项；配小字：“归属不等于执行顺序”。
3. **验证通过 ≠ 验收完成。** 展示真实的独立阶段记录；小字：“以保存的证据和决定为准”。
4. **计划变了，记录也要一起变。** 同一虚构项目变更前后；小字：“先保存记录，可见页面每 5 秒读取更新”。
