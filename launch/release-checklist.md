# Public release checks

This is a pending release checklist, not evidence that a release has occurred. Record actual command results in the release verification output.

- [ ] Export the explicit public allowlist into a fresh directory with no Git history; inspect its inventory for personal paths, real project records, credentials and unintended assets.
- [ ] Confirm the archive includes README, license, dependency manifest/lockfile, runtime assets, fictional demo, adapter contract and companion skill.
- [ ] In a fresh unpacked directory, install the documented dependencies and run the documented tests and fictional `demo` command.
- [ ] Run `init`, `check` and `open --no-open` against a temporary project. Verify initialization writes only `.delivery-board` files and preserves existing data on repeat use.
- [ ] Demonstrate the actual demo evolution: saved source changes appear with automatic refresh; paused polling and invalid-source stale behavior remain visible and truthful.
- [ ] Review screenshots and the video against the fictional source records. Ensure local verification, human acceptance and delivery are not conflated.
- [ ] Validate the companion skill frontmatter and review the listed scenarios. Label written expectation reviews separately from any executed agent evaluations.
- [ ] Check the final archive's README commands from its extracted location. Record the artifact path and checksum; do not claim a registry install exists unless it was actually published and verified.
- [ ] Before using the released social copy, verify the real public repository/download URL and attach that actual entry point. Publishing remains a separate authorized action.
