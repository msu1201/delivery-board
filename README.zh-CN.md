# Delivery Board

**知道现在做什么、它在整个项目中的位置，以及后面哪些任务依赖它。**

本地运行的只读依赖看板。可以展示任务、模块、阻塞、当前工作和用户闭环；项目记录变化时，图也会变化。公开素材全部使用虚构旅行项目 Wayfarer。

![虚构旅行项目演示](launch/assets/demo-overview.png)

## 先看效果

安装 Node.js 22 或更新版本。从 GitHub 页面点击 **Code → Download ZIP**，解压，在工具目录打开终端：

```sh
npm ci
npm run demo
```

会自动打开浏览器。终端输出实际地址和进程 PID；已有端口被占用时使用其他空闲端口，不停止其他服务。再次运行可以复用看板。

## 接到自己的项目旁边

仍然在工具目录执行，把示例路径换成自己的项目：

```sh
npm run init -- "/你的项目路径"
npm run open -- "/你的项目路径"
```

只创建项目里的 `.delivery-board` 目录，包含配置、空任务图和维护说明；不会修改业务代码，也不会覆盖已有看板。初始化不会自动分析代码并猜测任务。

你可以按[数据格式](docs/ADAPTER-CONTRACT.md)填写，也可以把[配套 Skill](skills/delivery-board/SKILL.md)交给编码助手，根据你确认的 roadmap 和任务文档整理。安装 Skill 需要把整个 `skills/delivery-board` 文件夹复制到助手支持的技能目录，并告诉助手工具解压在哪里。它不会替你虚构依赖、验收或完成状态。

```sh
node src/entry.js check "/你的项目路径"
```

可选：在工具目录运行一次 `npm link`，之后在任意目录使用 `delivery-board open "/你的项目路径"`。这是本地命令链接，不需要 npm 上已经有同名发布包。

## 项目变了，看板也会变

计划调整确认后，先更新项目记录。页面可见时，每次读取完成后约五秒再次读取；可暂停，随时手动刷新。切到后台后暂停轮询。内容没变时不重画图；更新时保留视野与仍然存在的选择。

打开虚构演示，再在另一终端运行：

```sh
node scripts/evolve-demo.js examples/travel-demo
```

观察新增任务、依赖变化和当前工作切换。恢复原演示：

```sh
node scripts/evolve-demo.js examples/travel-demo --reset
```

看板同步的是**最新成功读取的保存记录**。聊天中的想法不会自动成为事实；配套 Skill 负责按工作流程维护记录，不是常驻执行器。读取出错时显示过期警告并保留旧图。

## 状态含义

蓝色进行中、绿色完成、紫色部分完成、橙色待验收、红色受阻、白色待开始、灰色未知。深色双边框表示选中。分组的 4/7 是完成了七项中的四项，不是正在做第四项。产品任务仅技术验证通过仍不等于验收或交付。

闭环有独立的本地验证、验收与交付记录，不能用关联任务的数量替代。缩略地图保留整体位置；详情栏可以拖宽。

## 安全边界与退出

看板只监听本机回环地址，只读配置允许的文件，没有业务写入接口、模型调用或遥测。初始化写入三个设置文件；演示脚本只改虚构演示。项目记录是否加入 Git 由你决定，工具不会擅自修改 `.gitignore`。

启动的是独立进程。按终端给出的 PID 在系统进程工具中停止，再删除工具目录即可移除应用；`.delivery-board` 记录和复制的 Skill 可以分别保留或删除。若使用了全局链接，可执行 `npm unlink -g delivery-board`。

当前已验证 macOS 本地环境；其他系统需要独立验收。MIT 许可证；尚未声称已发布 npm 包、公开演示站点或已通过所有平台验证。完整命令与开发测试见 [English README](README.md)。
